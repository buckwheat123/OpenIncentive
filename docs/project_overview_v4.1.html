02项目功能矩阵

五大能力域覆盖「导入 → 计算 → 沟通 → 归档 → 运维」全链路。

① 数据导入 版本化

季度大表 + 年度通知信数据 + 用户花名册，三张核心表。

  • 季度大表：一张 CSV 覆盖员工/KPI/目标/实绩/Curve，逐行校验
  • 表内后行覆盖前行（latest-wins），员工信息合并跨行
  • 同表新建上级 + ADMIN 代理回退
  • 员工身份字段变更 → 旧记录封存为 UserVersion

② 冲突拦截 E2b

通知信数据 vs 季度计算数据的一致性守门。

  • 展开后 (period, employee, plan, KPI) 与 current BonusPlan 目标比对
  • 预览即标记「与季度计算数据冲突」并拦截
  • 独立 conflicts.csv：四个 existing_qN 列 + 逐季 old vs new
  • 计算数据为权威，通知信绝不静默覆盖

③ 计算引擎 两步式

Curve 配置 + 预览 + 提交，双阶段防误算。

  • Curve 达成率→支付率映射表由管理员配置
  • 预览批次不落库；正式提交生成 CalcRun + BonusResult
  • 特殊调整（单人 / CSV 批量 / 增量 / 留痕）
  • 多 BG 一键封存 · 支持全选

④ 通知信 E1

Global 模板 + 计划/绩效两张表占位符。

  • ADMIN 撰写 Global 模板，BG_ADMIN 可见可 fork 不可改写
  • PLAN_TABLE 仅结构（KPI/权重/目标/Curve）
  • PERFORMANCE_TABLE 逐 KPI 实绩/达成/曲线/原始率/加权贡献
  • 占位符可替换全部数据表字段；已阅追踪；ADMIN 群发

⑤ 角色视图 分区

同一份数据，四种视角。

  • 员工：个人奖金、KPI 明细、通知信
  • 多层经理：可管理下属链，逐层可见
  • BG 管理员：多对多管理多个 BG，成员合并视图
  • 平台 ADMIN：跨 BG + 代操作（代理 BG 管理员）

⑥ 导出 & 归档 双表

总支付率表 + 各 KPI 明细表，CSV 带 UTF-8 BOM。

  • 跨批次取 (员工, 计划) 最新结果，封存记录不丢失
  • 新增 sealed 列 + weighted_contribution_pct
  • 所有导入 / 调整 / 封存 / 群发写入 DataOpLog
  • 软删除（is_deleted） + 版本（is_current）

⑦ 业务连续性 运维

整库快照、一键回滚、空白起步。

  • backup.py：SQLite 在线备份 API，服务器运行中可安全拷贝
  • manifest 含 git rev / 完整性 / 各表行数
  • restore.py：还原前自动再做一次快照 + 漂移警告 + 服务锁检测
  • reset_empty.py：空 schema + 一个 ADMIN，用于演示与排错

⑧ 双语 & 翻译 i18n

界面 + 数据字段值双层翻译。

  • Translator.t() 静态字符串（支持命名占位符）
  • Translator.tl() 数据库字段值翻译（如 BG 名）
  • 语言管理页维护 Label 表 · 无 locale 文件
  • CSV 响应统一加 \ufeff BOM 保证 Excel 中文不乱码

06锁定规则与关键约束

这些规则跨批次稳定生效，任何后续改动都需保持一致。

加权支付率口径
weighted_rate = Σ(weight_pct / 100 × rate)，按原状加权加总、绝不归一化；系统不提供未加权（简单平均）支付率。
Plan vs Performance 两表拆分
PLAN_TABLE 只呈现计划结构（KPI / 权重 / 目标 / Curve，不含实绩与支付率）；PERFORMANCE_TABLE 逐 KPI 呈现权重 / 目标 / 实绩 / 达成率 / Curve / 原始率 / 加权贡献。
Latest-wins（表内后行覆盖前行）
同一 (期间 + 员工 + 计划 + KPI) 重复行，后出现的行覆盖先前值，员工信息跨行合并。
冲突处理权威源
通知信数据 vs 季度计算数据：以季度计算为准。冲突行预览即拦截，执行二次校验确保不写入；提供 conflicts.csv 供用户修复原表后重传。
BG 多对多
UserManagedBg 关联表；User.bg 保留为主属 BG 以兼容既有分区逻辑；bg_scope 用 lazy="selectin"，Jinja 渲染不触发 MissingGreenlet。
员工信息版本化
覆盖身份字段前，先落一条停用的 UserVersion（新信息启用、旧信息停用封存）；/person 页向管理员开放历史。
Global 模板只读规则
LetterTemplate.bg == "Global" 对所有 BG_ADMIN 可见、可另存为（fork）但不可直接改写；仅平台 ADMIN 可编辑原始 Global 模板。
无迁移 · 需重建
数据库以 Base.metadata.create_all 建表，无 Alembic / 无迁移——任何模型字段变更都需 seed.py 重建，或用 reset_empty.py 起空库。
CSV BOM 强制
所有 CSV 响应前置 \ufeff BOM 保证 Excel 中文不乱码；测试断言 startswith 前须 lstrip("\ufeff")。
年度→季度展开
year_to_big_text() 把一行年度数据展开为最多四行大表数据（period=year-Qn，quota=ytd_qn），空白季度跳过；对已是大表形状的输入原样透传。
快照与还原
restore 前 自动再做一次快照，错误的还原本身可撤销；备份含 DB 副本与签名密钥 → backups/ 必须 gitignore。
数据留痕
所有导入 / 调整 / 封存 / 群发都写入 DataOpLog；软删除（is_deleted）+ 版本（is_current）+ imported_at 三件套贯穿全表。

08快速开始

# 1) 建 venv + 装依赖
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

# 2) 造演示数据（含 BGA1 双 BG / BGA2 共管 / HR 越权探针）
.venv\Scripts\python seed.py

# 3) 启动
.venv\Scripts\python run.py            # 或 uvicorn app.main:app --reload

# 4) 访问
#    http://127.0.0.1:8000  · 登录 ADMIN / admin123

# 运维
.venv\Scripts\python backup.py pre_release     # 快照
.venv\Scripts\python restore.py latest         # 回滚
.venv\Scripts\python reset_empty.py            # 空白起步

# 测试
.venv\Scripts\python tests\test_calc.py
.venv\Scripts\python tests\test_e2e.py
